# 0) 硬性工程约束（必须遵守）
1. **单文件可运行**：全部逻辑在一个 HTML 内；使用 ES module `import`；禁止混用旧式全局 `THREE` UMD。
2. **版本锁**：`three` 与 `examples/jsm/*` 必须同版本；给出可复制粘贴的 import 示例（`OrbitControls`、`EffectComposer`、`RenderPass`、`UnrealBloomPass`、`RoomEnvironment` 或等价环境贴图方案）。
3. **摄像机与震动**：创建一个 `THREE.Group`（例如 `cameraRig`），将 `PerspectiveCamera` 作为子对象挂入；`OrbitControls` 绑定 `camera`。爆发震动**只叠加在 `cameraRig.position`（必要时极少量 rotation）**，每帧 `controls.update()`。禁止把 OrbitControls 的目标绕进会抖动的父节点导致交互失效。
4. **地形与粒子“同一份高度场”**：在 JS 中维护一份 `TERRAIN_GLSL` 字符串（包含同参数 FBM / domain warp），同时注入到：
   - `MeshStandardMaterial` 的 `onBeforeCompile`（改顶点高度）
   - 粒子系统的 compute/vertex（采样高度、地面碰撞、沿坡流动）
   必须写清楚 **world-space xz 对齐规则**（地形 mesh 的变换要一致），并用有限差分实现 **坡度向量**（泥石流沿切向滑移 + 摩擦阻尼），禁止“口头碰撞”。
5. **地形法线与内置材质的衔接**：在 `MeshStandardMaterial` 上改高度时，法线必须与当前 Three 版本的顶点管线一致，使 `transformedNormal` / 光照链路完整；避免出现“塑料折面”或着色器无法链接的结构性错误（实现方式由作者自行选择，以可编译、法线可信为准）。
6. **CPU 与着色器分工**：地形高度若在 CPU 侧做初始化（如粒子出生高度），须与 `TERRAIN_GLSL` **同一套数学**；JavaScript 中勿直接沿用 GLSL 内置函数名（如 `fract`），以免运行时报错。
7. **Three.js 现代管线与“世界坐标”陷阱（强烈建议自检）**：在 `MeshStandardMaterial` / `MeshPhysicalMaterial` 的 `onBeforeCompile` **片元**里若使用世界坐标（伪二次反弹、距热点 `length(world.xz)` 等），**不得默认**存在 `vWorldPosition`。在 **r150+** 的典型 `meshphysical` 着色器里，`varying vec3 vWorldPosition` **往往仅在 `USE_TRANSMISSION` 等少数宏开启时才会声明并赋值**；无 transmission 时直接引用会导致 **Fragment shader 未编译 / VALIDATE_STATUS false**。可靠做法：顶点里增加自定义 `varying`（例如 `vVcWorldPosition`），对**位移后的**顶点用 `(modelMatrix * vec4(p, 1.0)).xyz` 写入，片元中只读该 varying。
8. **从 `TERRAIN_GLSL` 裁剪子串给天空等 ShaderMaterial**：若用 `String.prototype.split` 去掉地形函数，**禁止**以子串 `'getTerrainHeight'` 分割——会切开 `float getTerrainHeight`，在 GLSL 中留下非法的孤立 `float`，同样导致片元编译失败。应使用完整声明边界（如 `'float getTerrainHeight'`）、或单独维护一份仅含 `vc_hash` / `vc_noise` / `vc_fbm` 的 `NOISE_GLSL` 常量，避免 fragile 字符串裁剪。
9. **JavaScript 模板字符串与着色器源码**：凡用反引号 `` ` `` 包裹整段 `vertexShader` / `fragmentShader` / `TERRAIN_GLSL` 时，**GLSL 注释内不得出现未转义的反引号**，否则会在浏览器中报 `Unexpected identifier`（模板字面量被提前闭合）。需要标注代码片段时用单引号或文字描述，或对反引号做转义。

# 1) “很好的全局光照”（浏览器可实现定义：必须按此实现）
> 说明：不要在 WebGL 里承诺路径追踪真 GI。请实现**高质量 IBL + 动态主光 + 接触暗部 + 岩浆二次照亮近似**，并严格遵守本节 **曝光预算** 与 **分阶段亮度曲线**，避免酝酿段过暗、爆发段整屏过曝或“洗天”。

## 1.0) 曝光预算（亮度分层，必须可辨）
把最终亮度当作**有限预算**分配；**禁止**单靠把 `toneMappingExposure` 或 Bloom `strength` 拉满来“显得亮”。

| 层级        | 职责                                       | 约束                                                                                                         |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 天空 / 天幕 | 蓝色或黄昏渐层 + 可读的云形纹理            | 爆发与溢流阶段仍须保留**色相与中高频细节**，不得被 Bloom/曝光漂成无纹理的亮灰/纯白片                         |
| 地形暗部    | 月光 + IBL + 极弱半球/环境填充             | 近景岩壁与远坡**不得糊成纯黑**；阴影区须保留可辨轮廓（靠 IBL + 弱 `HemisphereLight` 地面抬底，而非暴力曝光） |
| 岩浆与口缘  | 主热源：点光 + 材质高温区 + **局部** Bloom | 高温溢出应**集中在口缘、溢流带与弹道轨迹**，不得把整幅穹顶“染成一盏灯”                                       |
| 烟雾        | 吸光、散射、可略被岩浆边缘染暖             | 爆发期加法/高 alpha 层须克制，避免把帧平均亮度整体抬穿                                                       |

## 1.1) 必须包含的技术组合（缺一不可）
1. **IBL / 环境贴图**：`PMREMGenerator` 从 `RoomEnvironment`（或等价 HDR）生成 `scene.environment`，供 `MeshStandardMaterial` 漫反射与镜面反射；IBL 强度须足以支撑**非爆发段**地形可读（若过暗，**先**略抬 `scene.environment` 强度或 PMREM 贡献，**不要**先把曝光翻倍）。
2. **月光主光**：冷色 `DirectionalLight`（低角度、**强度克制**），配合 **极弱** `HemisphereLight` 或 `AmbientLight`：**天空半球偏冷、地面半球极弱偏暖或中性**，抬底阴影但**不**抹平口缘月光阴影形状。
3. **火山口动态点光源**：橙红 `PointLight`，**必须**设置合理的 `distance` / `decay`（或与版本等价的衰减参数），使能量主要落在口缘与近场；强度与 `phaseT` 绑定，**禁止**无衰减点光把半座山洗成同一亮度。
4. **色调映射与色彩空间**：`renderer.outputColorSpace = SRGBColorSpace`（或当前版本等价 API）；使用 `ACESFilmicToneMapping` 或与 Three 版本一致的**安全默认** `toneMapping`，避免线性输出导致整体发灰或过曝。

## 1.2) 分阶段亮度旋钮（须由 JS 按 `phaseT` 平滑曲线驱动，禁止硬阶跃）
下列为**建议起始区间**（可按镜头尺度微调，但须遵守相对关系：**爆发峰禁止**同时把曝光、点光、Bloom 三者都推到周期内最大值）。

- **`renderer.toneMappingExposure`**：酝酿 **0.70–0.90**；爆发峰相对酝酿仅 **+0.03 ~ +0.10**（禁止 +0.25 量级暴涨）；溢流 **略高于酝酿或持平**；冷却 **缓降** 至 **0.65–0.88**，周期首尾衔接处**禁止**闪黑到纯黑场。
- **`UnrealBloomPass`（或等价）**：
  - `strength`：酝酿 **0.25–0.55**；爆发峰 **≤ 1.1**；若天幕仍发糊发白，**优先**降 `strength` / 收窄 `radius`，**其次**略提 `threshold`，**最后**才微动曝光。
  - `threshold`：酝酿 **0.82–0.98**；爆发可短时降至 **0.65–0.88**；**禁止**长时间低于 **0.55** 导致全屏糊 Bloom。
  - `radius`：**0.35–0.55**（爆发峰可短时微升）；过大易把云层与天空晕接成一团。
- **`PointLight.intensity`**：酝酿约为爆发峰的 **8%–22%**；爆发峰为周期内热源顶点，但与曝光微抬 + 中等 Bloom 叠加后口缘高光仍可辨层次；冷却用 `smoothstep` 或指数衰减趋近 **0**。

**同一帧约束**：**禁止**出现「`toneMappingExposure` 周期最高 + `PointLight.intensity` 周期最高 + Bloom `strength` 周期最高」**三重叠加顶点**。爆发冲击力应主要来自 **粒子密度、抛射、相机震动与局部高光 Bloom**，而非全局曝光翻倍。

## 1.3) 光照与后期平衡（避免洗天）
点光、环境/半球、曝光与 Bloom **线性叠加**；全屏 Bloom 会抬高中高频，即使天空不受点光直射也可能过亮。原则：**宁可略暗、层次完整的天与云，不可亮到色相与云纹不可辨**；Bloom **只让真正高温像素**显著溢出。若使用半分辨率 Bloom，注意云层混叠；可选对天空材质略压入 Bloom 前输入、或对天空单独合成权重（实现任选，以验收取准）。

## 1.4) 伪二次反弹（强烈建议）
- 地形 `onBeforeCompile`：极克制 **rim / bounce tint**（面向热点在暗部混暖色，**mix 权重峰值建议约 0.04–0.12**），避免整片岩壁通体发红。
- 烟雾：加法/半透明 + **depth-aware** 厚度；亮缘可被岩浆染暖，但整体不抬穿天幕。

## 1.6) 反模式（明确禁止）
- 用过高 `toneMappingExposure` 补偿欠曝的 IBL/补光（会连带洗亮天空）。
- 爆发期长期压低 Bloom `threshold` 导致烟雾、云层、远景全域发糊。
- 关闭或极度削弱环境/半球，仅靠岩浆与 Bloom“照亮”场景（易导致酝酿段过暗）。

# 1.5) 天空、云层与烟柱的交互（建议作为观感目标）
- **天幕基调**：须有**可辨识的蓝色或黄昏渐层**（渐变或穹顶均可），与深色地形、暖色岩浆形成**冷暖对比**；避免默认纯黑背景；**全周期**天幕须保持可读的色相带，禁止爆发期把渐层推成接近 **#FFFFFF** 的平场。
- **高空云层**：柔和、大尺度云形（噪声或贴图），缓慢漂移；云层底色的**最大亮度**在爆发峰建议仍低于口缘岩浆最亮区一档，以便读出云纹；若 Bloom 仍吃云，**优先**略降云材质 albedo/emissive 或云 pass 对 Bloom 的贡献，而非再抬曝光。
- **烟柱冲云**：酝酿—爆发—溢流阶段，烟柱密度与上升动量增强时，应能读出**云被顶开、冲散或局部变薄**（透明度、采样偏移、与 `phaseT` 同步的权重等）；该效果强度曲线须与 **# 3** 中 `cloudDissolveWeight` / 曝光与 Bloom 曲线**同相**，避免云与烟各演各的。冷却后冲云效应**随烟势同步回落**。
- **喷发期护天**：冲云可以局部变白变透，但**须保留条带状或块状的云结构可辨性**；禁止整片天穹与云层融成无结构亮斑（与 **验收标准 9** 一致）。

# 2) 粒子系统架构（必须分层，禁止单一粒子包办一切）
至少三层（每层独立参数与 blend 模式），总量由 **GPGPU 纹理边长**决定（常见为三层同尺寸，故总粒子数约为 **3 × 边长²**）。在目标机器允许时，可采用**较大边长**（例如约 `128√10` 量级）以显著加厚**岩浆与烟体**的采样密度；低配须支持**整档下调边长**并仍保持分层架构与物理一致性。须在交付说明中交代**性能与边长的取舍**。

## A) 火山口“颗粒床 / 碎屑层”
- 在火山口区域预布一层**高密度静止或弱抖动粒子**（代表松散火山渣/浮石层）。
- **阶段二爆发**：对该层粒子施加**径向+切向冲量**，让火山口缘材料被**撕裂抛射**（不是只从点源发射新粒子），形成“整块口缘被带走”的震撼感。
- **阶段三**：颗粒床持续提供**溢流熔岩源项**：从火山口环形/多点采样发射“熔岩溪流粒子”（不是纯抛物线烟花），初速度沿坡度向外，带黏滞与分离力（可用简化：hash 邻域排斥 / 低密度扩散），在坡面形成发光网络。
- **运动可信度**：溢流与坡面滑动应体现**重力与下坡趋势**；避免使用无物理约束、易在水平方向来回振荡的“装饰性扰动”，以免熔岩在坡上出现**倒流、抽风式抖动**等与直觉相悖的观感。

## B) 爆炸抛射（弹道主导）
- 短窗口高密度喷发，拖尾火星可选。

## C) 烟雾 / 火山灰
在无风条件下，阶段一必须呈现：
1. **从口缘/喷口缓慢抬升的烟柱**（上升速度随时间增大，粒子半径/alpha/散射强度随时间增大）。
2. **蘑菇云结构**：烟柱上升到阈值高度后，出现**帽状扩散**（水平径向速度分量增大、垂直速度减小），形成“茎 + 帽”的轮廓；可用分层噪声驱动水平涡旋/卷曲，但**不得像随机乱飘的雪花**。
3. **密度演进**：0–4s 内从稀疏到浓密，遮挡月光并在爆发前制造压迫感。
4. **团块感与非轴对称**：烟体应呈现**絮状、团状**的体积暗示，而不是一根僵硬的圆柱；茎部可有**随高度缓慢变化的半径与轻微摆动**，帽部可有**切向卷曲**，整体仍保持可读的蘑菇轮廓。
5. **与全局时间的连续衔接**：进入冷却段后，**新生烟雾应逐渐稀少、上升与扩散动力逐渐减弱**，已有烟团**opacity / 饱和度缓慢下降**并转为灰白余烟；避免在阶段边界上出现**发射与力场瞬间归零**的硬切。

实现提示（任选其一但要写清楚）：
- 多层 billboard / instanced quads + curl noise 偏移；或
- 体积近似：同层粒子多次叠加 + soft particle（深度 fade）

# 3) 全局时间轴（必须由 JS 驱动 uniform，禁止只靠 shader `mod(time)`）
用 `phaseT ∈ [0,20)`（JS 计算）驱动下列量，且**全部**对 `phaseT` 使用 **smoothstep / 缓动曲线**（禁止阶段边界硬切），使天、云、烟、光、后期在同一时间轴上可读：

**必须绑定的 uniform / 参数（至少）**  
`PointLight.intensity`（及衰减相关）、`renderer.toneMappingExposure`、`UnrealBloomPass.strength` / `threshold` / `radius`（或等价）、各层粒子**发射率**与力场强度、`cameraRig` 震动幅度、烟帽扩散系数；若实现天幕与冲云，还须绑定 **`cloudDissolveWeight`**（或等价命名：云被冲散/变薄/透明度调制的 0–1 权重）、云层 UV 偏移或形变强度。

**光照与后期相对节奏（与 # 1.2 一致，此处为时间相位）**  
- **酝酿**：曝光与 Bloom 处于**基线**；点光弱；`cloudDissolveWeight` 低。  
- **爆发**：点光先 **smoothstep 升峰**；Bloom `strength` 可中幅升高、`threshold` 可**短时**略降；`toneMappingExposure` **仅微抬**（见 # 1.2）；**禁止**三者同时顶格。  
- **溢流**：点光可从爆发峰**略回落**仍保持口缘热感；Bloom 维持中高但 `threshold` 不宜长期过低；曝光略低于或持平爆发峰。  
- **冷却**：点光、Bloom `strength`、曝光**先后或同步缓降**（非同一帧瞬间清零）；`cloudDissolveWeight` 随烟势回落；至周期末曝光仍处在可读底噪区间（见 # 1.2），避免接回酝酿时闪黑。

建议阶段（可微调，但逻辑必须可见；每段内的光/烟/Bloom 须符合上节相对节奏）：
- **0–4s 酝酿**：蘑菇云烟雾从小到大；点光源微弱脉动；颗粒床轻微鼓动；`toneMappingExposure` / Bloom 为基线；`cloudDissolveWeight` 缓升但保持天幕可读。
- **4–6s 爆发**：弹道粒子暴增；颗粒床大规模抛射；shake 强；点光源达峰（仍遵守 # 1.2 三重非叠加顶点）；烟柱与帽快速膨胀；`cloudDissolveWeight` 达阶段峰，冲云可读但护天（# 1.5）。
- **6–14s 溢流与泥石流**：**持续从火山口溢流** + 已落地熔岩沿坡度滑移（高温保持至少数秒，不得触地瞬间冷却）；弹道成分衰减；点光/Bloom/曝光按溢流段曲线，避免长时间“洗天”。
- **14–20s 冷却**：**新粒子与强发射逐步收束**（而非某一帧突然“关闸”）；温度场与亮度全局缓慢下降；颜色从亮黄红转暗岩色；Bloom、点光、`toneMappingExposure` **平滑**渐弱至接近熄灭但**末段仍有弱可读底光**；`cloudDissolveWeight` 回落；**既有烟雾在数秒内继续漂移、扩散并变淡**，最终转为灰白色余烟，再与周期起点衔接或淡入重置。

## 3.1) 粒子寿命与“流体感”
- 各层粒子的**可见存续时间**应与镜头尺度匹配：过短会导致熔岩与烟体像**闪烁的火星/碎点**，难以形成**连贯的拖尾与团块体积**；在性能允许的前提下，烟雾与溢流层宜采用**相对长的寿命或较慢的 age 衰减**，使观众能读完一段流动轨迹。
- **寿命衰减与阶段曲线应对齐**：进入冷却后，宜**减慢死亡速率**或**降低单位时间的新生成权重**，让画面上的消亡与**光照、发色的变暗**同步，避免“光还没熄，粒子先全没了”的错位感。

## 3.2) 规模与镜头（“壮观”）
- 在点精灵 / billboard 方案下，需通过**合适的屏幕空间尺度**（与距离、FOV 协调）与**口缘附近的粒子密度**，让爆发与烟柱在画面中占据**足够体量**；仅靠提高纹理分辨率而单粒子过小，远看仍会显得单薄。

# 验收标准（模型自检）
1. 0–4s 能明显看到**烟柱变粗变高 + 帽状扩散**（蘑菇云轮廓）；烟体有**团块与轻摆**，而非一根僵直细柱。
2. 爆发时火山口缘**颗粒床被带走**（不是只有中心点源）。
3. 6–14s 能明显看到**火山口持续溢流**（不是只有爆炸烟花）；坡面流动**顺重力与下坡**，无明显**倒流或高频抽风式抖动**。
4. 地形受 **environment + 方向光 + 点光源 +（可选）暖色暗部 tint** 共同作用，画面不再“塑料平面”；**酝酿段（0–4s）**远坡与岩壁阴影区仍可见轮廓，**不得**大面积死黑（满足 # 1.0 曝光预算）。
5. OrbitControls 全程可用，震动不破坏交互。
6. **14–20s 冷却**：能感知到**新烟与强上升逐渐变少、旧烟缓慢变淡变灰**；不应出现**冷却一开始烟雾与力场立刻全停**的断裂感；周期末衔接酝酿时**不得**整屏闪黑。
7. 溢流与烟雾在单周期内**轨迹可读、寿命足够长**，整体更接近**流体与体积**而非稀疏噪点。
8. 若实现天幕：可见**蓝色或黄昏天空与高空云层**；烟柱强盛阶段能读出**云被冲散或局部变薄**，冷却后云势与烟势**同步回落**。
9. 爆发与溢流高光下，**天空与天云仍保留层次与色相**，不出现整片天被 Bloom/曝光**漂成无细节亮斑**的现象；**禁止**出现 # 1.2 所述**曝光+点光+Bloom 三重同时顶格**。
10. **4–6s 爆发峰**：口缘与弹道可极亮，但**天幕渐层与云纹仍可辨**；画面整体**不得**长时间处于“灰白蒙版”或口缘高光**完全.clip 成无层次白块**占满大半屏。
11. **控制台自检**：无 `THREE.WebGLProgram` / `Fragment shader is not compiled` / `Unexpected identifier` 等错误；地形片元若需世界坐标，须满足上文 **0.7** 的自定义 `varying` 约束，不得在无 `USE_TRANSMISSION` 时假定存在 `vWorldPosition`。
