洛希极限模拟动画 Prompt
--------------------------------

请使用 Three.js (通过 CDN importmap 引入) 编写一个完整的、基于 Web 的 3D 演示，模拟"月球突破洛希极限并坠毁于地球"的天文灾难场景。所有代码必须写在一个单独的 HTML 文件中，不依赖任何外部图片或资源文件。

根据以下详细的"视觉与逻辑描述"来构建完整的场景。

---

**1. 整体视觉风格与环境：**

*   **渲染风格：** 场景应该非常明亮、清晰，光照充足，确保用户能看清所有细节。请启用 `THREE.ACESFilmicToneMapping` 色调映射，`toneMappingExposure` 设为 1.2 左右。
*   **多光源照明：** 不要只使用单个方向光。请至少设置：一个环境光 (AmbientLight)、一个主方向光 (模拟太阳)、一个补光 (Fill Light，从另一侧照亮暗面)。确保场景整体明亮，没有全黑的死角。
*   **星空背景：** 必须创建一个由至少 2000～3000 个随机分布的白色小点组成的球形星空背景 (`THREE.Points`)，包裹整个场景。不可省略。
*   **参考线：** 在地球周围的 XZ 平面上绘制一个清晰可见的红色虚线圆环 (`THREE.LineDashedMaterial`)，标注出"洛希极限"距离。在圆环旁边添加一个 `THREE.Sprite` 文字标签，显示"ROCHE LIMIT"。圆环的透明度应有缓慢的呼吸脉冲动画。

---

**2. 程序化纹理（地球）：**

由于不加载外部图片，地球纹理必须用 Canvas 2D API 程序化生成。**请特别注意纹理质量。**

*   **地球纹理 (至少 2048×1024 canvas)：**
    *   海洋底色：使用从深蓝 (#0D47A1) 到亮蓝 (#2196F3) 的**纵向渐变**，不要只是单色填充。
    *   大陆：绘制 6～8 个大陆块。每个大陆的轮廓必须使用 `quadraticCurveTo` 或 `bezierCurveTo` 绘制**有机的、不规则的边缘形状**，绝对不能只是随机散布的圆形。大陆使用不同深浅的绿色 (#4CAF50, #66BB6A, #81C784 等)。
    *   地形细节：在每个大陆上叠加一些更小的随机色块（深绿、亮绿），模拟山脉和平原的色彩变化。
    *   云层：用 `globalAlpha = 0.25` 的半透明白色，绘制约 50～60 个大小不一的圆形，模拟云团。
    *   极地冰盖：在 canvas 顶部和底部绘制白色到透明的线性渐变，模拟极地冰雪。

**3. 角色定义：**

*   **地球 (半径设为 5 单位)：**
    *   使用 `MeshStandardMaterial`，贴上述程序化纹理，设置 `roughness: 0.7`, `metalness: 0.1`。
    *   **双层大气光晕（必须实现）：**
        *   **内层 (FrontSide)：** 一个略大于地球的半透明球体，使用自定义 ShaderMaterial 实现 Fresnel 边缘发光效果 (rim = pow(1.0 - dot(viewDir, normal), 2.5))。颜色为浅蓝色，使用 `AdditiveBlending`。
        *   **外层 (BackSide)：** 一个更大的球体，同样使用 Fresnel shader，但 side 设为 `THREE.BackSide`，rim 指数更高 (3.5)，制造更宽泛的外围辉光。
    *   地球应有缓慢的自转动画 (rotation.y)。

*   **月球（重要！月球不是一个 Mesh，而是陨石碎块组成的球形集群）：**
    *   **核心概念：月球由约 70 个独立的大陨石碎块（MoonChunk）紧密排列成球形组成。** 不要创建任何月球 Mesh 或月球纹理。这些陨石碎块本身就是月球的骨架结构。
    *   **球形排列：** 使用 Fibonacci 球面分布算法将碎块均匀排列在三个层次中：
        *   外壳层（~40 个，半径 0.78～1.0 倍 MOON_RADIUS，size 0.18～0.36）
        *   中间层（~20 个，半径 0.4～0.78，size 0.12～0.26）
        *   核心层（~10 个，半径 0～0.45，size 0.14～0.32）
    *   每个碎块都记录自己相对于月球中心的 `localOffset`（局部偏移向量）。
    *   **月海色差：** 根据碎块在球体上的角度位置，部分区域的碎块用更深的灰色（模拟月海暗区），其他区域用较浅灰色（高地），实现类似月球表面的明暗变化。
    *   **碎块外观（陨石风格，不能是光滑几何体！）：**
        *   使用 `IcosahedronGeometry(size, detail)` 作为基础几何体，大碎块 detail=1（42 顶点），小碎块 detail=0（12 顶点）。
        *   **随机拉伸轴：** 每个碎块在 X/Y/Z 各轴乘以 0.7～1.3 的随机系数，让碎块有长条形、扁平形等不规则基础形状。
        *   **多层噪声位移：** 对每个顶点，基于其法线方向施加三层叠加的径向噪声位移：大尺度凸起 (amp = size×0.25)、中尺度凹凸 (amp = size×0.12)、小尺度粗糙 (amp = size×0.06)。可用 3D hash 函数。
        *   **陨石坑凹陷：** 每个碎块随机生成 2 个"撞击坑"方向，将该方向附近的顶点向内凹陷。
        *   **flatShading: true** 突出岩石的硬棱角面片质感。
    *   **壳层小陨石（Shell Chunks，必须实现，数量远多于大碎块）：**
        *   在所有陨石碎块的最外层，覆盖约 5000 个极小的陨石 Mesh（不是粒子点！），使用 `createMeteoriteGeometry(size, 0)` 生成，size 约 0.05～0.11，`flatShading: true`。均匀分布在 MOON_RADIUS × (0.97～1.05) 的球面上。
        *   **作用：** 大碎块数量少（~70 个），壳层小陨石大量覆盖（~5000 个）形成月球的完整表面外观。这样月球看起来表面致密完整，同时大碎块提供破碎时的戏剧性视觉效果。
        *   **接近阶段：** 壳层小陨石跟随 moonCenter 同步移动，与碎块一起构成完整月球外观。
        *   **进入洛希极限后：** 所有壳层小陨石同时释放为独立物理体，继承月球当前速度，并附加**切线方向的旋涡速度分量**（通过 crossVectors 计算垂直于地月轴的切线方向），使小陨石以漩涡状抛洒向地球，与碎块瓦解层次同步。
        *   **性能优化：** 壳层小陨石完全不做碰撞爆炸效果，不做燃烧效果。仅用距离判断（< EARTH_RADIUS × 1.2）直接隐藏消失，节省算力。
        *   颜色为浅灰色（0.45～0.65 灰度），`castShadow: false`。
    *   **月球不自转。** 现实中月球被潮汐锁定，且自转会导致后续物理模拟中碎块位置错乱。
    *   **月球没有震动/抖动动画。** 破碎过程完全由物理力驱动，不需要人工震动效果。

**4. 动画流程与物理模拟（纯物理驱动，请严格实现）：**

所有物理更新必须基于 `THREE.Clock` 的 `getDelta()` 返回的 dt (delta time) 进行计算，确保动画速度与帧率无关。

**核心物理模型（极简纯引力，不使用内聚力）：** 每个碎块在释放后只受一种力：
*   **地球引力**（每个碎块独立计算）：`F_gravity = G_earth / dist_to_earth²`，方向朝向地球中心。

**不要实现内聚力 (cohesion)。** 之前版本使用内聚力会导致碎块在进入洛希极限后先内聚再反弹的不自然震荡效果。正确做法是：进入洛希极限后，所有碎块瞬间释放为独立物理体，仅受地球引力。由于每个碎块到地球的距离不同，靠近地球的碎块引力更强、加速更快，自然率先飞出；远离地球的碎块引力更弱、加速更慢。这个**引力差**本身就是潮汐力的本质，自然产生"剥洋葱"的分层效果，**不需要内聚力衰减、人工释放阈值、侵蚀前锋或 Shader 裁剪**。

*   **阶段一 — 接近 + 逐个脱离 (Approach with per-chunk Roche detection)：**
    *   维护一个 `moonCenter` 位置，初始在洛希极限外一个月球直径处（`MOON_START_DISTANCE = ROCHE_LIMIT + MOON_RADIUS × 2`），让玩家能看清月球从远处缓慢接近的过程。
    *   **接近速度极慢且逐渐加速：** 基础速度设为 `APPROACH_BASE_SPEED = 0.005`（极慢）。使用二次加速曲线：`speedMult = 1 + progress² × 9`，其中 `progress = 已行进距离 / 总距离`。
    *   **每个碎块独立检测洛希极限（关键！不是整体释放！）：**
        *   每帧遍历所有未释放碎块，先计算其世界坐标 `worldPos = moonCenter + localOffset`。
        *   如果 `worldPos.length() <= ROCHE_LIMIT`（该碎块自身进入了洛希极限），则**单独释放该碎块**，赋予 moonCenter 的当前速度。
        *   未过线的碎块继续跟随 moonCenter。已释放的碎块运行独立物理（地球引力）。
        *   壳层小陨石同理：单独检测、单独释放，释放时额外获得切线旋涡速度。
    *   **效果：** 靠近地球的碎块先到达洛希极限、先脱离飞向地球；远地球侧的碎块还在跟随月球继续接近。形成自然的逐层剥离效果。
    *   **混合状态处理：** approach 阶段中已有碎块在坠落、燃烧、撞击，因此撞击检测和火焰尾迹必须在 approach 阶段也生效。
    *   可以有轻微的 Y 轴 sin 波浮动。
    *   当所有碎块都已释放后，进入阶段二。

*   **阶段二 — 全体坠落 (Falling)：**
    *   所有碎块已释放，各自独立受地球引力加速坠向地球。
    *   **moonCenter 作为参考点继续受地球引力加速向地球坠落**（仅用于 UI 显示和追踪，不影响碎块物理）。
    *   **重要：不要使用内聚力。** 内聚力会导致碎块先聚拢再反弹的不自然震荡。

*   **阶段三 — 坠落与大气燃烧 (Falling & Atmospheric Entry)：**
    *   碎块各自独立坠落，无碎块间碰撞检测，只检测与地球的碰撞。
    *   **大气层交互：** 当碎块距离地球中心 < 大气层半径（地球半径 × 1.15）时：
        *   `material.emissive` 设为橙红色 (#ff4400)，`emissiveIntensity` 随深入大气层增大。
        *   `material.color` 逐渐 lerp 到橙色。
        *   **必须实现独立的火焰尾迹粒子系统：** 共享的 `THREE.Points` + 自定义 shader，使用 `AdditiveBlending`。

*   **阶段四 — 撞击与爆炸 (Impact & Explosion)：**
    *   碎块距地球中心 ≤ 地球半径时判定为撞击。
    *   **关键实现细节（易出 bug，请注意）：** 碎块的 `update()` 方法中检测到碰撞时，只设置 `impacted = true` 标志，**不要**在同一帧内同时设置 `alive = false`。在动画循环中，必须**先遍历处理所有 `impacted` 碎块**（生成爆炸效果、隐藏 mesh、设置 alive=false），**然后**再用 `if (!alive) continue` 过滤存活碎块做火焰尾迹。否则同帧设置 `alive=false` 和 `impacted=true`，再用 `!alive` 跳过，会导致爆炸效果永远不触发。
    *   **撞击爆炸效果（不要用简单的圆片缩放！）：**
        *   爆炸粒子系统：从撞击点沿地表法线喷射 30～60 个粒子（亮黄→橙→暗红）。
        *   环形冲击波：额外 20～30 个环形扩散粒子。
        *   大碎块撞击时创建临时 `PointLight`（橙色，强度 8，范围 15），1.5 秒后衰减消失。
        *   地表烧灼痕迹：半透明红色/橙色圆形 Mesh，缓慢淡出。
    *   所有碎块撞击完毕后进入"模拟完成"状态。
